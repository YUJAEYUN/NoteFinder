# NoteFinder — DART 발행어음 후보 검토 하네스

> **현재 상태: 실험용 프로토타입**
> 이 저장소는 DART 공시에서 `발행어음`이 등장한 문맥을 모아 사람이 검토할 수 있게
> 만드는 도구입니다. 현재 구현만으로 발행어음 보유액을 완전·자동 확정하는 제품은
> 아닙니다.

## 해결하려는 문제

DART 본문검색에서 `발행어음`을 찾으면 다음 자료가 함께 검색됩니다.

- 특정 증권사, 상품명, 금액이 같은 표 행에 있는 실제 보유 내역
- `중금채, 발행어음 등`처럼 여러 상품이 한 금액으로 합쳐진 내역
- 발행어음형 CMA, 인가 제도, 영업 현황 등의 설명 문장
- 정정 전·후 공시와 동일 내용의 반복 문맥

목표는 검색 결과를 억지로 하나의 숫자로 만드는 것이 아니라 **후보를 누락 없이 보존하고,
확정 가능한 값과 수동 검토 대상을 분리하며, 모든 판단을 원문까지 추적 가능하게 만드는
것**입니다.

## 중요한 용어와 범위

### 증권사 탐지는 발행사 판정이 아니다

코드는 특정 발행어음 인가 증권사 목록을 사용하지 않습니다. `삼성증권`, `키움증권`,
`NH투자증권` 등 문맥에 명시된 모든 `*증권` 형태를 원문 표기 그대로 후보로 보존합니다.
`KB증권`과 `케이비증권` 같은 표기 통합은 추출 정규식에 하드코딩하지 않습니다. 향후
회사코드와 유효기간을 가진 별도 엔터티 레지스트리에서 처리해야 구 사명이나 인가 변동을
감사 가능하게 관리할 수 있습니다.

그러나 문맥에 증권사명이 있다는 사실만으로 그 회사를 다음 중 어느 하나로 자동 확정하지
않습니다.

- 발행어음 발행사
- 판매사 또는 중개사
- 투자·거래 상대방
- 공시 제출인 자신
- 제도 설명에 예시로 등장한 회사

즉, **증권사명 매칭은 증거 추출 단계**이고 **발행사 및 보유액 확정은 별도 검증 단계**입니다.
현재 코드는 후자의 의미 판별을 완전히 자동화하지 못합니다.

### 금액 분류

- `A`: 같은 문맥에 증권사명·`발행어음`·금액이 있음. 자동 확정값이 아니라
  **확정 검토 우선 후보**입니다.
- `B`: 중금채·기타금융상품 등 복수 상품의 합산액입니다. 발행어음 금액으로 집계하면
  안 됩니다.
- `REVIEW`: 증권사 또는 금액의 연결 관계가 불명확합니다.
- `EXCLUDED`: 상품·제도 설명이고 연결된 금액이 없는 것으로 규칙이 판단했습니다.

`EXCLUDED`도 삭제하지 않고 원문 문맥과 제외 사유를 Excel에 남깁니다.

## 권장 수집 전략

### 1. DART 본문검색을 후보 인덱스로 사용

[DART 공시통합검색의 상세검색](https://dart.fss.or.kr/dsab007/main.do)에서 다음 조건으로
찾은 결과는 좋은 시작점입니다.

- 본문 내용: `발행어음`
- 기간: 필요한 분석 기간(예: 최근 1년)
- 공시 유형: 정기공시

검색 건수는 조회 시점과 조건에 따라 변하므로 README에 고정된 전체 건수로 간주하지
않습니다. 검색 결과는 최종 데이터가 아니라 **분석할 접수번호 후보군**입니다.

### 2. 후보 접수번호를 CSV로 준비

현재 하네스는 DART 웹 화면을 자동 스크래핑하지 않습니다. 화면의 내부 요청은 공개
OpenDART API 계약이 아니며 변경될 수 있기 때문입니다. 검색 결과에서 접수번호를 확보해
UTF-8 CSV로 준비해야 합니다.

```csv
rcept_no,rcept_dt,corp_name,corp_code,report_nm
20260318001234,20260318,예시회사,00123456,사업보고서 (2025.12)
```

필수 열은 `rcept_no` 하나입니다. 나머지는 추적성과 정정공시 판별을 위해 권장합니다.
DART 검색 결과를 CSV로 안정적으로 자동 수집하는 기능은 **아직 구현되지 않았습니다**.

### 3. OpenDART 원문을 내려받아 로컬에서 재검증

후보 접수번호별 `document.xml` ZIP을 OpenDART에서 내려받고 `data/raw`에 캐시합니다.
이후 ZIP 안의 XML/HTML에서 키워드가 있는 표 행과 텍스트 문맥을 추출합니다.

```text
DART 본문검색 후보
  → 접수번호 CSV
  → OpenDART document.xml 원문 ZIP 및 로컬 캐시
  → 키워드 문맥 추출
  → 증권사·금액·단위 후보 탐지
  → A / B / REVIEW / EXCLUDED 분류
  → Excel 및 감사 JSON
```

이 방식은 모든 정기공시 원문을 먼저 내려받는 방식보다 빠르지만, DART 본문검색 자체가
놓친 문서는 함께 놓칠 수 있습니다. 완전성 검증이 필요하면 동일 기간의 정기공시 전체
수집 결과와 후보 검색 결과를 비교해야 합니다.

## 설치

Python 3.10 이상을 권장합니다.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

API 키는 저장소에 넣지 않고 환경 변수로 전달합니다.

```bash
export OPENDART_API_KEY="<your-api-key>"
```

이미 채팅이나 로그에 노출된 키는 재발급하고 기존 키를 폐기하는 것이 안전합니다.

## 실행

### DART 검색 후보만 분석

```bash
python main.py \
  --candidates dart_search_candidates.csv \
  --keyword "발행어음" \
  --output issued_note_report.xlsx
```

### 해당 기간의 정기공시 전체 분석

```bash
python main.py \
  --begin 20260101 \
  --end 20261231 \
  --keyword "발행어음" \
  --output issued_note_report.xlsx
```

전체 분석은 공시 수와 API 호출량이 커질 수 있습니다. 후보 방식과 전체 방식 모두 내려받은
접수번호별 ZIP을 `data/raw`에서 재사용합니다.

## 출력

Excel 워크북에는 다음 시트가 생성됩니다.

| 시트 | 내용 |
|---|---|
| `confirmed` | 현재 규칙의 `A` 후보. 최종 집계 전 원문 확인 필요 |
| `needs_review` | 합산형 `B` 및 불명확한 `REVIEW` 후보 |
| `excluded` | 설명형으로 분류된 후보와 제외 근거 |
| `dedup_log` | 정정공시 중복 제거 과정에서 교체된 접수번호 |

각 후보에는 접수일, 접수번호, 제출인, 보고서명, 원문 파일명, 원문 문맥, 탐지된 증권사,
원문 금액·단위, 천원 환산값, 분류 및 이유가 포함됩니다.

`<output>.audit.json`에는 조회 방식, 조회·분석 문서 수, 증거 행 수, 중복 제거 로그가
기록됩니다.

## 현재 구현의 한계

이 항목들은 구현 완료 기능이 아니라 후속 작업입니다.

1. DART 본문검색 결과를 접수번호 CSV로 자동 변환하지 않습니다.
2. 병합 셀과 다단 헤더를 완전히 복원하지 않아 당기·전기 또는 취득원가·장부가액 열을
   잘못 연결할 수 있습니다.
3. `A`는 같은 문맥에 필수 토큰이 있다는 뜻이지, 회계적으로 확정된 보유액이라는 뜻이
   아닙니다.
4. 같은 문맥의 여러 숫자를 모두 후보로 만들기 때문에 날짜·이자율·전기 금액이 섞일 수
   있습니다.
5. 증권사 이름을 찾더라도 발행사·판매사·거래상대방 역할을 자동 판정하지 않습니다.
6. 정정공시 중복 제거는 현재 `법인 + 정정 표기를 제거한 보고서명` 기반 휴리스틱이며,
   정정 관계 API를 이용한 확정 판정이 아닙니다.
7. DART 검색 후보 방식만 사용하면 검색 색인에서 누락된 공시는 찾을 수 없습니다.

따라서 현재 결과는 **자동 집계 결과가 아니라 검수 대기열**로 사용해야 합니다.

## 검증 순서

1. `needs_review`의 합산형이 `confirmed`에 들어가지 않았는지 확인합니다.
2. `confirmed`의 원문 문맥에서 상품명·증권사 역할·금액 열·단위를 직접 확인합니다.
3. 동일 표의 당기/전기, 취득원가/장부가액을 구분합니다.
4. `dedup_log`의 최신 공시 선택이 실제 정정 관계와 일치하는지 확인합니다.
5. 일부 기간은 전체 정기공시 방식으로 교차 실행해 본문검색 후보의 누락률을 측정합니다.
6. 검수 결과를 고정 fixture로 추가하고 회귀 테스트를 실행합니다.

```bash
python -m unittest discover -s tests -v
```

## 다음 구현 우선순위

1. DART 검색 결과의 접수번호를 합법적이고 재현 가능한 방식으로 가져오는 어댑터
2. 표의 병합 셀·다단 헤더·단위·당기/전기 열 복원
3. 증권사의 문맥상 역할(발행사/판매사/거래상대방) 분류
4. DART 정정 관계를 사용한 중복 제거
5. 사람이 확정/반려한 결과를 다시 학습 데이터와 회귀 fixture로 반영하는 검수 루프
