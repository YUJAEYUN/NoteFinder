# 🎯 dart-issued-note-scanner

금융감독원 DART 정기공시의 본문과 주석을 스크리닝해 법인별 **발행어음(Issued Note) 매입 현황과 자금 운용 규모**를 정량적으로 추출하고, 판단 근거와 함께 Excel로 내보내는 도구입니다.

## 1. 프로젝트 목표

DART 정기공시 및 첨부문서에서 `발행어음`이 등장하는 자료를 수집한 뒤 실제 투자 내역과 상품·제도 설명을 구분합니다. 최종적으로 다음 항목을 연결한 정형 데이터를 만드는 것이 목표입니다.

- 법인명(제출인)
- 보고서 및 기준 연월
- 발행어음 매입처(증권사)
- 매입·보유 금액과 단위
- 만기일 또는 보유 기간
- 데이터 신뢰도와 그 산출 근거

> 핵심 원칙: 문서에 명시되지 않은 발행어음 금액을 합산 금액에서 임의로 추정하지 않습니다. 확정할 수 없는 값은 별도의 유형과 비고로 보존합니다.

## 2. 데이터 파이프라인

```text
DART 원문 수집
  → 문서·표·주석 텍스트 정규화
  → 상품 설명 및 제도 안내 노이즈 필터링
  → 발행어음 인가 증권사 매칭
  → 정정공시 중복 제거
  → 신뢰도 및 산출 근거 태깅
  → Excel 출력
```

### 2.1 원문 수집 및 정규화

OpenDART API에서 정기공시 목록과 원문·첨부문서를 수집합니다. HTML 표의 병합 셀, 줄바꿈, 공백, 숫자 천 단위 구분자와 금액 단위를 정규화하되, 감사 가능한 결과를 위해 원문 문맥과 접수번호를 함께 보존합니다.

금액을 표준화할 때는 문서에 표시된 `원`, `천원`, `백만원` 등의 단위를 반드시 읽어 출력 단위로 환산합니다. 원문 값과 원문 단위도 별도 필드로 남겨 환산 오류를 검증할 수 있게 합니다.

### 2.2 상품 설명 및 제도 안내 노이즈 필터링

KB금융·신영증권 사례처럼 다음 내용은 기업의 실제 매입 내역이 아니라 상품 또는 제도 설명일 가능성이 높습니다.

- 발행어음형 CMA의 상품 설명
- 발행어음 인가 확대 등 제도 안내
- `가입대상`, `IMA`, `법규상의 규제`, `불특정금전신탁` 등이 중심인 문장
- 같은 표 행이나 가까운 문맥 안에서 금액을 찾을 수 없는 경우

이러한 결과는 정량 집계에서 제외하되, 재검토가 가능하도록 `제외 사유`와 원문 문맥을 기록합니다. 단순히 금액이 없다는 이유만으로 원문 자체를 삭제하지 않습니다.

### 2.3 발행어음 인가 증권사 매칭

문서에서 아래 증권사 명칭과 표기 변형을 정규표현식으로 탐색해 매입처를 정규화합니다.

- NH투자증권
- 한국투자증권
- KB증권
- 미래에셋증권

증권사명이 없거나 여러 상품이 하나로 합산된 경우에는 매입처를 `미정`으로 유지합니다. 증권사 목록은 인가 현황 변경에 대응할 수 있도록 코드에 고정하지 않고 설정으로 관리하는 것을 권장합니다.

### 2.4 정정공시 중복 제거

동일 법인이 같은 보고서 기준 연월에 정정 보고서를 제출하면 중복 합산될 수 있습니다. 다음 키로 문서를 묶고, 접수일자와 접수번호를 기준으로 최신 문서만 집계 대상으로 선택합니다.

```text
제출인(법인 식별자) + 보고서 종류 + 보고서 대상 연월
```

제목의 `[기재정정]` 여부만으로 판단하지 않으며, 제외된 이전 접수번호와 최신 접수번호를 중복 제거 로그에 남깁니다.

### 2.5 신뢰도 및 산출 근거 태깅

#### Type A — 확정형

예: `NH투자증권 | 발행어음 | 11,200`

증권사, 상품명, 금액이 같은 표 행 또는 명확히 연결된 문맥에서 1:1로 대응합니다. 문서의 금액 기준(취득원가·기말장부가액 등)을 비고에 명시합니다.

#### Type B — 합산형

예: `기타금융상품(중금채, 발행어음 등) | 35,960,207`

여러 상품의 합계만 제공되어 발행어음 금액을 분리할 수 없습니다. 합계는 참고 값으로 기록하되 발행어음 확정액에는 포함하지 않고, `기타금융상품 합산액 분리 필요`라고 표시합니다.

#### 제외형 — 설명·제도 노이즈

상품 설명이나 제도 안내만 존재하고 실제 보유 금액과 연결되지 않는 결과입니다. 정량 출력에서는 제외하고 제외 근거만 감사 로그에 남깁니다.

## 3. Excel 출력 구조

| 접수일자 | 접수번호 | 법인명(제출인) | 시장구분 | 보고서명 | 기준연월 | 매입처(증권사) | 보유 금액(천원) | 원문 금액/단위 | 만기/보유 기간 | 유형 | 산출근거 및 비고 |
|---|---|---|---|---|---|---|---:|---|---|---|---|
| 2026-07-23 | 예시 | 아이씨티케이 | 코스닥 | 사업보고서 | 2025.12 | NH투자증권 | 11,414 | 11,414천원 | 2025.05~2026.05 | A | `[확정]` 주석의 기말장부가액 |
| 2026-07-03 | 예시 | 빅솔론 | 코스닥 | 사업보고서 | 2025.12 | 미정 | 35,960,208 | 35,960,208천원 | - | B | `[합산]` 중금채·발행어음 등 기타금융상품 합계 |
| 2026-06-29 | 예시 | 리딩투자증권 | 기타 | 사업보고서 | 2026.03 | 자사/미정 | 80,000,000 | 80,000백만원 | - | 검토 | `[기관]` 금융기관 자체 계정 여부 확인 필요 |

> 위 행은 출력 형식을 설명하기 위한 예시입니다. 실제 수집 결과로 간주하거나 그대로 합산하지 마세요.

권장 워크북 구성은 다음과 같습니다.

- `confirmed`: Type A 확정 데이터
- `needs_review`: Type B 및 수동 검토 대상
- `excluded`: 노이즈로 제외된 결과와 제외 사유
- `dedup_log`: 정정공시 중복 제거 내역

## 4. 시작하기

### 4.1 환경 설정

```bash
python -m venv .venv
source .venv/bin/activate
pip install pandas openpyxl requests beautifulsoup4
```

### 4.2 OpenDART API 키 설정

API 키는 소스 코드나 Git 저장소에 직접 기록하지 말고 환경 변수로 전달합니다.

```bash
export OPENDART_API_KEY="<your-api-key>"
```

이미 채팅, 로그 또는 저장소에 노출된 키는 OpenDART에서 재발급한 뒤 기존 키를 폐기하는 것을 권장합니다. `.env`를 사용할 경우 반드시 `.gitignore`에 추가합니다.

### 4.3 실행

```bash
python main.py \
  --begin 20260101 \
  --end 20260729 \
  --keyword "발행어음" \
  --output "issued_note_report.xlsx"
```

실행 하네스는 정기공시 목록을 페이지 단위로 가져오고, 접수번호별 원문 ZIP을
`data/raw`에 캐시한 뒤 모든 XML/HTML 조각에서 후보 문맥을 수집합니다. 네트워크
재시도 때 원문을 다시 받지 않으므로 같은 입력을 반복 검증할 수 있습니다.

결과물은 Excel 외에도 `<출력명>.audit.json`을 생성합니다. 감사 파일에는 조회 조건,
조회·분석한 공시 수, 추출한 증거 수, 정정공시 제거 내역을 기록합니다. 원문 자체를
삭제하지 않고 `confirmed`, `needs_review`, `excluded`, `dedup_log`로 라우팅하기 때문에
규칙이 놓친 후보도 나중에 다시 확인할 수 있습니다.

### 4.4 단계별 내부 검증

1. **수집 검증**: DART 상태 코드를 검사하고 응답 ZIP을 접수번호 그대로 보존합니다.
2. **완전성 검증**: 키워드가 있는 표 행과 주변 문맥을 모두 후보로 만들며 금액이 없어도
   `REVIEW` 또는 `EXCLUDED`에 남깁니다.
3. **정규화 검증**: 원문 금액·단위와 천원 환산값을 함께 저장합니다. 단위가 없으면
   환산값을 비워 두어 잘못된 숫자 추정을 방지합니다.
4. **분류 검증**: 확정형만 `confirmed`, 합산형과 불명확형은 `needs_review`로 보냅니다.
5. **중복 검증**: 법인·보고서 기준으로 최신 접수만 분석하고 교체 관계를
   `dedup_log`와 감사 JSON 양쪽에 기록합니다.
6. **회귀 검증**: 아래 명령으로 확정형, 합산형, 정정공시, 워크북 라우팅을 검사합니다.

```bash
python -m unittest discover -s tests -v
```

## 5. 검증 원칙

- Type A만 발행어음 확정액 집계에 포함합니다.
- Type B의 합계는 발행어음 금액으로 간주하지 않습니다.
- 숫자와 상품명이 같은 행에 있어도 다단 헤더와 열 병합을 복원한 뒤 의미를 확인합니다.
- 동일 공시 내 당기·전기 금액을 구분하고 보고서 기준일에 해당하는 열만 선택합니다.
- 표마다 금액 단위를 확인하고 환산 전·후 값을 모두 보존합니다.
- 모든 결과에서 DART 접수번호, 문서 위치, 원문 근거를 역추적할 수 있어야 합니다.

## 6. 후속 개발 계획

- 대기업 재무제표의 `단기금융상품` 주석 세부 내역을 탐색하는 2차 딥 크롤링
- 표 구조 인식과 당기·전기 열 판별 고도화
- LLM을 활용한 Type B 문맥 분류 및 검토 보조
- 수동 검수 결과를 반영하는 규칙 기반 회귀 테스트 데이터셋 구축

LLM은 합산액을 근거 없이 분해하거나 금액을 생성하는 용도가 아니라, 후보 문맥 분류와 검토 우선순위 지정에 한해 사용합니다.
